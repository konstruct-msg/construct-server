# `.well-known/construct-server` — зеркало, не источник

Файл рядом — **копия** того, что отдаёт `https://konstruct.cc/.well-known/construct-server`.
Клиент забирает его отсюда по raw-ссылке:

```
https://raw.githubusercontent.com/konstruct-msg/construct-server/main/.well-known/construct-server
```

## Зачем

До 2026-08-18 адрес забора был один. Манифест несёт не только список релеев, но и
`bundle_signing_key` — ключ, которым проверяются сертификаты отправителя в sealed sender и
prekey-бандлы. Без него клиент не стартует чисто. Одно имя, один регистратор, один хостинг: проблема
с доменом и проблема с конфигурацией были одной и той же проблемой.

Зеркало на GitHub-raw существовало и было убрано 2026-06-12 вместе с obfs4/WebTunnel — тогда
манифест перестал нести что-то срочное для пользователя под блокировкой, и вместе с этим ушла
единственная запасная точка. Возвращено осознанно и с другим обоснованием.

## Почему это безопасно

Файл подписан Ed25519, подпись проверяется ключом **в бинарнике клиента**
(`VeilCertFetcher.verifySignature`). Ни `konstruct.cc`, ни GitHub не являются якорем доверия — оба
отдают байты, которые подписали мы. Хост не может подменить содержимое, он может только не ответить.

Отсюда и смысл зеркала: оно добавляет **второй домен отказа** — другой DNS, другой регистратор,
другой оператор.

## Чего это стоило

Гонка в `fetchAndCacheRelayConfig` берёт первый ответ, прошедший проверку подписи. При двух хостах
победитель определяется скоростью ответа, а подпись говорит, кто написал манифест, и никогда — когда.
Поэтому вместе с зеркалом появилось правило свежести: `RelayManifestFreshness` в клиенте отвергает
манифест старше уже принятого, и отвергает манифест без читаемого `signed_at`, если датированный уже
есть. Без этого второй источник давал бы выбор отката тому, кто умеет замедлить первый.

## Как обновлять

**Правится всегда первым `construct-landing/.well-known/construct-server`**, он же источник. Сюда
копия кладётся байт-в-байт, тем же коммитом или сразу следом.

Расхождение не опасно — подпись не сойдётся либо файл окажется старее и будет отвергнут по
`signed_at`, — но устаревшее зеркало бесполезно ровно тогда, когда нужно. Проверка:

```bash
diff <(curl -s https://konstruct.cc/.well-known/construct-server) \
     <(curl -s https://raw.githubusercontent.com/konstruct-msg/construct-server/main/.well-known/construct-server)
```

Пустой вывод — копии совпадают.
